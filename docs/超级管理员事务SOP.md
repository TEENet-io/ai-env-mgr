# 超级管理员事务 SOP

版本：2026-09-29。适用：`windows-control` 数据库模式及其连接的 Windows Agent、LiteLLM、OSS 和阿里云无影。本文按一次业务变更组织，不按后台菜单组织。

## 1. 角色和事务边界

系统当前没有名为 `superadmin` 的独立角色。本文的“超级管理员”指后台的 `admin` 角色；`operator` 执行日常开户、绑定、预算和指定机器等操作，`viewer` / `security` 只读。涉及操作系统、数据库、云平台、GitHub 或 LiteLLM 的步骤，需要相应平台权限；拥有后台 `admin` 身份并不自动拥有这些权限。

一次事务从明确对象和影响范围开始，到**执行结果被验证并留痕**结束。点击按钮、任务显示“已提交”或 Agent 报告“同步成功”，都不等于业务结果已经验收。跨 Admin、网关、OSS 和云电脑的操作不是一个数据库原子事务：中间失败时，按每项 SOP 的补偿步骤继续，不假定系统自动回滚。

每次事务至少记录：事务编号、发起原因、对象与影响范围、申请人/执行人、变更前状态、批准依据、操作时间、后台任务 ID 或发布版本、验证结果、未完成项和后续责任人。高风险变更建议第二人复核；当前系统**没有内置双人审批**，不能把建议写成已实现的强制门禁。记录中不要粘贴密码、AK/SK、网关令牌或会话原文。

| 编号 | 事务 | 主要触发条件 | 完成的判据 |
|---|---|---|---|
| S01 | 授予或收回后台管理员权限 | 人员入职、转岗、离职、账号风险 | 角色和登录状态正确，交接/撤权留痕 |
| S02 | 员工紧急撤权与到期清理 | 离职、令牌泄露、违规使用 | 网关令牌失效；云账号与实例按期限处理 |
| S03 | 设备注册、重装与注销 | 新镜像、令牌丢失、设备退役 | 设备身份唯一，绑定和状态正确 |
| S04 | 修改全局浏览器/AppLocker 策略 | 安全策略变更、误封、应急测试 | 抽样机器实际生效；临时放宽已恢复 |
| S05 | 暂停/恢复模型渠道并下发 | 云供应商故障、欠费、模型下架 | 网关权限和客户端目录符合预期 |
| S06 | 发布或回滚 Agent/Codex | 新版本、安全修复、故障回滚 | 目标机器回报目标版本，异常机有处置 |
| S07 | 审核并安装其他软件 | 员工申请机器级软件 | 包、安装结果、可启动性均通过 |
| S08 | 采集开关与留存清理 | 合规确认、期限到期 | 采集范围经批准，删除有回执 |
| S09 | 配置告警、通知和令牌轮换 | 值班和安全策略变更 | 测试通知成功，自动任务状态正常 |
| S10 | 升级 Admin/数据库 | 控制台发布、数据库迁移 | 健康检查通过，关键业务路径可用 |
| S11 | 备份、恢复与密钥轮换 | 定期演练、故障、密钥风险 | 备份可恢复；新密钥可用，旧密钥安全撤销 |
| S12 | 处置全局故障或安全事件 | 大面积离线、误发布、凭据泄露 | 先止损，再恢复，最后复盘 |

## 2. 各事务操作

### S01｜授予或收回后台管理员权限

**前置检查**：确认申请人的职责和最小必要角色；`admin` 可改全局策略、发布目标和管理其他管理员，不作为普通查看账号发放。核对至少还有一名可登录的 `admin`。

1. 到 **设置 → 管理员**，按申请创建 `admin`、`operator`、`security` 或 `viewer`。初始密码仅显示一次，经受控渠道交给本人，不放进工单或群聊。
2. 要求本人首次登录绑定验证器、保存恢复码，再到 **我的账号** 修改密码。核对列表中的“已绑定”、最近登录和角色。
3. 撤权时在同页停用对应账号。停用会结束该账号的登录会话；核对状态为“停用”。不能停用当前登录的自己，需由另一名 `admin` 操作。

**完成/异常**：新账号用本人身份完成一次登录验证；撤权账号不能再登录。误停用可由其他 `admin` 启用；验证器丢失或只剩最后一名管理员可登录时，不用共享他人账号绕过，按认证恢复流程处理并记录。

### S02｜员工紧急撤权与到期清理

**前置检查**：核对 Windows 用户名、邮箱、绑定机器、离职或事件生效时间；先分清“立即禁止调用”和“7 天后清理云资源”。普通关户可由 `operator` 执行，超级管理员负责跨系统和例外处置。

1. 在 **员工账号 → 员工详情** 执行“关户”，核对网关令牌吊销和配置撤回任务。不要先解绑机器：绑定关系让 Agent 知道该清理哪个 Windows 用户的凭据。
2. 在 LiteLLM/调用侧验证旧令牌不能再调用；在 **任务中心、审计、机器日志** 核对撤权送达。离线机器未清理本地文件时，网关侧吊销仍应先挡住调用。
3. 云资源管理员在阿里云停用云账号、关闭实例。按客户确认的期限（当前业务流程为离职满 7 天）删除云账号、释放实例及数据，再到机器页注销设备。
4. 如涉及原始会话、账单或个人数据删除，另执行 S08；后台“删除员工账号”或“注销机器”不等于全链路数据删除。

**完成/异常**：网关拒绝旧令牌、Admin 员工状态为已离职、云实例关闭、到期清理有凭证。任一步失败按同一员工重试并核查任务详情；不因页面显示“关户”就宣告云侧资源已删除。

### S03｜设备注册、重装与注销

**前置检查**：确认机器主机名、云电脑实例、绑定员工三者一致。制作镜像前在模板机执行 `agent.exe prepare-image`，不能把设备令牌复制进镜像。

1. 全新且从未绑定的机器开机后可自行注册。曾经绑定、发过令牌或注销过的主机名，在 **机器详情 → 允许注册（24 小时）** 开窗口后再启动/重装 Agent。
2. 如果怀疑设备令牌泄露，先在机器页“吊销令牌”；它会同时放行短时间重新注册。若需阻止此主机继续取得凭据，应先关户/解绑并安排机器下线，不能把“吊销令牌”误当永久封锁。
3. 核对详情页“直连控制台”、令牌签发时间、最后上报、本机用户 profile、绑定员工和凭据投递状态。只有确认实例永久下线后才“注销机器”。

**完成/异常**：主机只出现一次，绑定正确且状态持续更新。若出现 `the report names another machine`，检查镜像是否残留设备身份；若注册超时，先查 Admin 健康和网络，不反复创建同名设备。

### S04｜修改全局浏览器/AppLocker 策略

**前置检查**：列出影响的全部机器和当前规则；优先缩小变更范围。全局开关会影响未绑定机器，AppLocker 的“审计”表示记录但**不拦截**。

1. 到 **设置 → 封禁策略** 修改域名清单或 AppLocker 放行目录。放行目录只接受机器级目录树（以 `\*` 结尾）；不能放行用户目录、Temp 或整盘。
2. 如需临时关闭网站拦截或切 AppLocker 审计，记录原因、开始时间和预计恢复时间，并通知值班人。这是全局安全放宽，不作为软件安装失败的常规解决办法。
3. 在至少一台在线机器核对策略同步、实际浏览器拦截和 AppLocker 执行模式；其余机器在总览检查版本/最后同步。测试结束恢复原开关并再次验证。

**完成/异常**：策略目标与机器实际状态一致，临时例外已关闭。机器未生效先看 Agent 日志和最后上报；不要连续提交相反策略掩盖同步故障。

### S05｜暂停/恢复模型渠道并下发

**前置检查**：确认故障在 AWS、Google 或 Azure 的哪个渠道、受影响模型和员工；同名模型可能有其他渠道副本，不能只按模型名判断影响。LiteLLM 的模型/价格/部署调整需在网关侧先完成。

1. 在 **员工账号 → 模型与渠道** 对目标渠道输入渠道代号确认暂停，记录原因。暂停会更新渠道策略，并给相关员工重新生成模型目录；若网关读取失败，页面会提示稍后“全部下发”。
2. 检查“模型下发”的逐人结果，先给一名测试员工下发并让其完成当前请求后重启 Codex 验证。再执行“全部下发”，核对已收到人数、失败原因和网关实际调用权限。
3. 恢复渠道前确认供应商故障已解除、价格和密钥可用；点“恢复”，重复测试员工和全量验证。

**完成/异常**：网关拒绝已暂停渠道的新调用，客户端模型目录与目标一致；恢复后测试调用通过。注意明确指定模型白名单的员工，若白名单里的模型全部来自暂停渠道，下发可能失败，需单独调整其可用模型。后台下发失败不代表渠道暂停自动撤销。

### S06｜发布或回滚 Agent/Codex

**前置检查**：取得构建来源、版本号、SHA-256、变更说明、最低 Agent 版本和一台可回滚的测试机器；不要复用同一版本号覆盖不同二进制。

1. CI 将包上传 OSS；到 **软件安装 → Agent/Codex 版本库** 点“立即扫描 OSS”。确认登记为“候选”、大小及 SHA-256 与构建产物一致。登记本身不会改变机器。
2. 用“指定给机器…”选测试机，在 **机器详情 → 版本记录** 和 Agent 日志核对下载、校验、安装、重启及功能验收。Codex 要用 Windows 真机检查能启动、模型目录和限制行为；构建成功不算验收。
3. 人工“标记已验收”后“批准稳定”；仅稳定版本可“设为全局”。输入版本号确认，再在总览/机器页追踪“当前/应装”和异常机器。
4. 出问题先“清除全局”阻止尚未更新的机器继续尝试，或把全局目标改回已验证的旧稳定版本；单独指定的机器须逐台改回旧版本或“跟随全局”。“清除全局”不会卸载已更新机器。

**完成/异常**：预期机器全部回报目标版本且关键功能通过，离线/失败机器有单独处理记录。旧 Agent 不支持定向发布时，不能假称已完成灰度；需安排人工真机验收或明确全局发布风险。

### S07｜审核并安装其他软件

**前置检查**：只接受公司批准的软件和来源。确认员工需求、目标机器、安装包版本、供应商签名/来源、静默参数、实际安装路径、检测文件和是否需要公共桌面快捷方式。EXE 的 `/S`、`/quiet` 等参数**不通用**，不能只看扩展名猜测。

1. 在 **软件安装 → 软件目录与安装** 上传 MSI/EXE 或填 URL。普通 EXE 必须填写静默参数；高级选项中核对检测路径、快捷方式目标和必要的 AppLocker 允许目录。微信当前模板默认 `C:\Program Files\Tencent\Weixin\Weixin.exe`，但仍以目标机器实际路径为准。
2. 等上传/审核任务结束，核对目录状态和 SHA-256。若要改变安装包字节，使用新版本号；修正旧 manifest 时，先检查是否有活动任务，避免在执行中改变任务的安装依据。
3. 先给一台测试机器创建安装任务，到 **后台任务中心** 看下载、校验、安装、检测与失败日志；在标准用户会话中点公共桌面快捷方式验证。通过后再扩大范围。
4. 失败先查安装日志和实际文件位置；取消旧任务、修正应用配置后创建新任务。删除目录项只删除 OSS 包和 manifest，**不会卸载已安装软件**。

**完成/异常**：任务成功、检测文件存在、标准用户可启动、AppLocker 不拦截。`standard-user launch check` 报路径不存在时先核对实际安装路径及 manifest 的检测/快捷方式目标，不要盲目重装或全局关闭 AppLocker。

### S08｜采集开关与留存清理

**前置检查**：取得客户对采集目的、员工范围、历史补传、存储地域、保留天数和删除例外的书面确认。原始会话可能含提示词、文件内容和个人信息。当前采集扫描范围与 API 上传授权对共享机器多用户存在差异；**该差异修复、测试和客户确认前，不应开启原始会话采集**。

1. 获准启用后，在 **设置 → 常规 → 采集开关** 配起始日期和静默秒数，先用测试机器验证范围、上传、权限和 OSS 路径，再扩大到生产。起始日期控制可补传范围，不是保留期限。
2. 需要停止新增时先关闭采集，核对 Agent 同步到关闭状态；关闭开关不会删除已上传数据、Windows 原文件和备份。
3. 在 **采集数据自动保留** 配保留天数；如需一次性删除过期对象，用“清理过期采集数据”并输入 `DELETE <天数>` 确认，在任务中心核对删除数量和失败项。

**完成/异常**：对象数量和范围与批准单一致，清理任务成功并有审计。此功能只清理 `data_collect/`，不代表员工、网关、SLS、数据库、Windows 原文件和备份的全链路删除；按[数据目录表](数据目录表_客户合规确认_2026-09.md)另行处理。

### S09｜配置告警、通知和令牌轮换

**前置检查**：确认值班接收人、告警阈值、令牌最长使用天数、每日轮换上限及离线机器处理口径。

1. 到 **设置 → 告警与轮换** 配告警开关、机器离线阈值、预算阈值和离职清理提醒天数；在 **通知渠道** 配 Webhook/邮件后分别点击发送测试，确认值班端真正收到。
2. 开启自动令牌轮换前核对当前员工令牌年龄和近期机器同步情况。轮换会吊销旧令牌并下发新令牌，离线机器可能被跳过，需在任务和员工列表跟踪。
3. 在 **告警** 页“确认”表示有人接手，不表示已解决；完成根因修复并核对条件消失后再关闭或等系统自动关闭。

**完成/异常**：测试通知到达、任务中心无持续失败、异常告警有负责人。变更通知密钥或 SMTP 密码时，先验证新配置可用再撤销旧凭据。

### S10｜升级 Admin/数据库

**前置检查**：有已验证的提交、变更窗口、数据库备份状态、回退版本和服务访问路径。后台部署脚本会重启 `ai-env-mgr-console`，Agent 长连接可能短暂断开并自动重试。

1. 在控制台主机的正确 checkout 上确认工作区无未提交改动，完成构建/检查。按[数据库模式部署](数据库模式部署.md)执行 `dist/deploy/deploy-console.sh`；脚本发现待迁移时先做数据库 dump，再迁移、替换程序和重启服务。
2. 验证 `systemctl` 服务状态、`/healthz`、后台登录、员工/机器读取、任务中心和一项非破坏性 Agent 同步。记录部署提交、迁移版本和重启时间。
3. 健康检查失败时脚本会恢复上一版程序；**数据库迁移不会自动回退**。先保留现场、确认新旧 schema 兼容，再决定是否执行数据库回退，不能盲目重跑脚本。

**完成/异常**：服务健康、关键页面和 Agent API 正常，失败任务有解释。不要把 Cloudflare 连接瞬断直接判为 Agent 身份错误，先看服务重启时间和后续重试。

### S11｜备份、恢复与密钥轮换

**前置检查**：区分“备份存在”和“备份可恢复”。数据库备份不包含所有 OSS 安装包/采集原文；主密钥文件须在数据库备份之外单独保管。

1. 定期核对 `ai-env-backup.timer` 最近成功时间、OSS `_backup/` 最新对象及保留期限；在隔离环境进行恢复演练，验证能登录、读取任务和解密凭据。演练不得连接生产网关执行写操作。
2. 真正恢复前冻结写入、记录恢复点和可能丢失的时间窗口；先验证备份及主密钥，再由数据库负责人执行恢复。恢复后重放恢复点之后的撤权和删除清单，防止旧令牌、已删数据或已取消任务“复活”。
3. 轮换主密钥或 OSS/网关/CI 密钥遵循“先加入新密钥 → 验证读写 → 迁移引用 → 撤销旧密钥”。主密钥具体步骤见[数据库模式部署](数据库模式部署.md)；不要先删旧密钥，否则历史密文可能无法读取。

**完成/异常**：恢复演练有时间、对象、校验和结果；轮换后关键链路通过且旧密钥已撤销。此项涉及云/数据库权限，不是 Admin 页面单击即可完成。

### S12｜全局故障或安全事件止损

**触发**：多台机器同时离线、错误版本全局发布、渠道不可用、异常令牌调用、采集超范围等。先标记事件开始时间和影响对象，指定一名处置负责人。

1. **先止损**：误发布清除或切回全局目标；渠道故障暂停对应渠道；令牌泄露关户/吊销；采集超范围立即关闭采集。只做与事件匹配的最小操作，不为修软件安装而关闭全网 AppLocker。
2. **再定位**：查 **总览 → 机器详情/日志、任务中心、告警、审计**；同时查 Admin 服务健康、网关和云平台。区分“控制台不可达”“Agent 离线”“机器休眠”和“任务失败”。
3. **分批恢复**：先测试机/测试员工，再扩大；记录每一批的目标版本、结果和未恢复名单。涉及外泄时轮换相关密钥并核对旧凭据失效。
4. **结束与复盘**：确认新请求、机器状态和用户侧功能恢复；补齐事件时间线、根因、影响范围、数据/费用影响和预防措施。

**完成/异常**：止损已被机器/网关实际验证，未恢复对象有责任人和预计时间。不能只凭“按钮已点”关闭事件。

## 4. 使用本 SOP 时必须知道的限制

- 后台“审核应用”目前是上传时由 `admin` 操作并记录，不是系统强制的双人审批；通用 EXE 的静默参数和安装结果必须靠测试机验收。
- 版本登记、任务创建和最终在员工桌面可用是不同状态。全局发布只允许稳定版本，但“稳定”仍需管理员对真机结果负责。
- 关闭采集、关户、注销机器、删除软件包是四种不同动作；它们不会互相完成对方的数据删除任务。
- 旧版[操作手册](操作手册.md)保留了 OSS 直连和早期发布流程的历史说明；与本 SOP 冲突时，以当前数据库模式后台界面和实际代码为准，再核对当时部署版本。
