# 控制台数据库模式:部署与切换清单

> 2026-09-18。对应分支 `rds-phase0`。设计见 `docs/superpowers/specs/2026-09-12-rds-unified-control-plane-design.md`(rev.4),进度见 `docs/superpowers/plans/2026-09-12-rds-phase0-1.md`。

## 一句话

同一个 `admin` 二进制,设了 `AIENVMGR_DB_DSN` 就是数据库模式:账号 + 验证器登录,页面读表,每个操作是"一个事务 + 排队任务",Worker 在进程内跑,OSS/SLS 用服务端身份。不设就是原来的 OSS 模式,行为不变。

## 环境变量(全部走 systemd `EnvironmentFile`,600)

| 变量 | 作用 |
|---|---|
| `AIENVMGR_DB_DSN` | `postgres://aienv_app:...@<rds 内网地址>:5432/aienv?sslmode=require`。**存在即启用数据库模式。** |
| `AIENVMGR_MASTER_KEY_FILE` | 信封加密主密钥文件,root 专属 0600。生成:`umask 077; printf '{"current":"k1","keys":{"k1":"%s"}}\n' "$(openssl rand -base64 32)" > /etc/ai-env-mgr/master.key`。**备份到数据库备份之外的地方**:没有它,库里所有令牌和验证器种子都打不开。 |
| `AIENVMGR_OSS_ACCESS_KEY_ID` / `_SECRET` | 服务端 OSS 身份(读写 `agent_workdir/`、`admin/`,读 SLS)。新 ECS 上改用 RAM 实例角色后撤掉。 |
| `AIENVMGR_GATEWAY_URL` / `AIENVMGR_GATEWAY_ADMIN_KEY` | 同原来。注意 URL 必须是员工桌面能访问的公网地址(`https://litellm.teenet.app`),它会被写进每个人的 `config.toml`。 |
| `AIENVMGR_SLS_PROJECT` / `AIENVMGR_SLS_ENDPOINT` | 同原来;数据库模式下用上面的服务端身份读。 |
| `AIENVMGR_PUBLIC_HOST` | 验证器应用里显示的名字,填 `windows-control.teenet.app`。 |
| `AIENVMGR_FIRST_ADMIN_EMAIL` | 首个管理员的邮箱(可空)。 |
| `AIENVMGR_WORKER` | `off` 时本进程不跑 Worker(第二个只出页面的实例用);默认跑。 |

## 首次启动

1. 数据库上用超级账号跑一次 `go run ./cmd/migrate up`(或直接启动控制台,它自己会迁移)。三个角色的密码单独设:`alter role aienv_app login password '...'` 等,见 `go/db/README.md`。
2. 启动控制台。首次启动会在主密钥同目录写一个 root 专属的 `first-admin.txt`(用户名和初始密码,**不进日志**),日志只提示文件位置。用它登录,页面会引导绑定验证器并显示十个恢复码,之后在"我的账号"改密码,**然后删掉这个文件**。
3. `/healthz` 返回 `ok` 即数据库可达;Cloudflare/systemd 的健康检查指到这里。

## 切换步骤(RDS 到位之后)

前提:旧控制台已停(阶段 1 期间不允许两个写入口)。

1. **只读导入**:用服务端 OSS 身份 + 网关管理密钥跑导入器(`internal/migrate.Importer`),把名册、策略、绑定、网关上的额度/模型/令牌别名、审计历史、默认额度读进库。可重复跑,不改 epoch,不发令牌。
2. **影子比对**(`internal/migrate.Comparer`,只读):看数据库要发布的对象和 OSS 里现有的差在哪。正常情况下只会剩一类差异——每个在用员工"有已发布凭据、库里无令牌明文"。
3. **逐人重发凭据**(控制台"重发"按钮):Worker 会在网关发新令牌、封存、写新的 `credentials.zip`,agent 下一轮换上并结束 Codex。旧别名 `emp-<user>` 的令牌在这一步被吊销。
4. 比对为空 → 切换完成。此后 OSS 对象由 Worker 生成,库是权威。
5. 撤销旧控制台用过的 admin AK;`sls-bootstrap` 之类临时 AK 一并禁用。

## 运行中的几件事

- **任务页**(导航 7):每个操作排的任务、失败原因、重试次数;"立即对账网关"按钮。判定为永久失败(400 类)的任务不再重试,要人看。
- **对账**每小时自动跑;发现"我们以为吊销了、网关还在服务"的令牌会直接删掉并在日志里记 `gateway_drift`。
- **审计投递**每分钟写到本机审计流(Logtail 采走),五分钟后回查 SLS 按 event_id 确认;查不到的一直留在待确认列表,不会默认成功。
- **机器状态**每分钟从 `_status/` 导入;agent 协议不变。
