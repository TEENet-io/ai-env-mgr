# 企业微信集成调研

给谁看：客户的 IT 管理员、开发同事。

要解决什么：

1. 把系统告警发到企业微信。
2. 进一步评估：能不能把 `admin` 做成企业微信机器人，怎么搭，安全上要守住哪些线。

---

## 0. 先认识几个词

客户说的"**微信企业版**"，就是现在的**企业微信**（英文名 WeCom 或 WeChat Work）。以前的"微信企业号"已经并入企业微信。

> ⚠️ **前提：客户必须已经在用企业微信。** 个人微信和普通微信群**没有官方的机器人接口**，只能通过企业微信实现。如果客户现在只有个人微信群，第一步是开通企业微信。

| 词 | 意思 |
|---|---|
| `admin` | 本系统给管理员用的程序，有命令行（CLI）和终端界面（TUI）两种用法。 |
| `admincore` | `admin` 底层的功能库，查机器、取日志、发布更新等操作都在这里。 |
| Webhook URL | 群机器人的专用地址。往这个地址发一段数据，消息就出现在群里。 |
| 回调 | 企业微信收到用户消息后，主动把消息转发到我们服务器上的某个地址。 |
| 自建应用 | 企业在企业微信后台自己创建的应用，可以收发消息。 |
| `access_token` | 调用企业微信接口时要带的临时凭证。 |
| 公网可达 | 互联网上任何人都能连到这台服务器。 |
| 全桶读写密钥 | 能读写整个 OSS 存储桶（存放安装包和配置的云存储）的密钥。 |

本方案分两部分：

- **① 通知**：简单，先做。
- **② 把 admin 做成能收发消息的机器人**：更进一步，需要加强安全。

---

## 1. 通知：用群机器人的 Webhook（最省事）

企业微信的每个内部群都能添加一个**自定义群机器人**，添加后会得到一个 **Webhook URL**。服务器往这个地址用 POST 方式发一段 JSON，消息就发进群了。**不用注册应用，也不用 `access_token`。**

- **支持的消息类型**：`text`（文字）、`markdown` / `markdown_v2`（带格式的文字）、`image`（图片）、`news`（图文）、`file`（文件）、`template_card`（模板卡片）。告警最适合用 markdown，可以加粗、变色、@某人。
- **发送频率限制**：每个群机器人大约每分钟 **20 条**，超过就会被限制。所以告警多的时候必须**合并**发送。例如"3 台机器离线（OFFLINE）"合成一条发，不要一台发一条。
- **方向**：基本**只能往外发**（服务器推到群里），**收不到群里的消息**。

### 怎么和本系统对接

写一个常驻后台的小程序，定时运行 `admin status`（直接用现有的 `admincore`），把下面这些情况推到企业微信群：

- 机器状态为 `STALE`（长时间没有更新）或 `NO REPORT`（没有上报），可能真的出故障了。
- 凭据过期，或员工已离职但还没处理（`DISABLED USER`）。
- 机器上出现计划外的账户（`EXTRA USERS`）。
- agent 自我更新的进度（各台机器的 agent 版本逐台更新）。

这个程序**只读数据，风险低，半天能做完**。这是满足客户"接入企业微信做通知"最快的办法。

> ⚠️ **Webhook URL 本身就相当于密钥**：谁拿到它，谁就能往群里发消息。不要提交到代码仓库，不要发给外人，不要贴在聊天记录里长期留着。

### 消息示例（markdown）

```jsonc
// POST 到 https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<KEY>
{
  "msgtype": "markdown",
  "markdown": {
    "content": "**AI Env Mgr 巡检告警**\n> 2 台需要关注：\n> - `DESKTOP-B` STALE（静默 4 天）\n> - `DESKTOP-D` NO REPORT\n<@zhangsan>"
  }
}
```

## 2. 把 admin 做成企业微信机器人（能收也能发）

群机器人**收不到消息**。想做到"给它发指令，它执行后回复"，要换一种做法。

### 2.1 两种做法

**做法一：自建应用 + 接收消息回调（常用做法）**

1. 在企业微信管理后台创建**自建应用**，拿到 **CorpID**（企业编号）、**AgentID**（应用编号）和 **Secret**（应用密钥）。
2. 配置**回调 URL**（接收消息的地址）、**Token** 和 **EncodingAESKey**（这两个用于签名校验和消息加解密）。
3. 用户在企业微信里给应用发消息后，企业微信把消息 **用 AES 加密**，再 POST 到我们的回调服务器。
4. 服务器**解密消息、识别指令、执行、回复**。回复可以是直接应答这次请求（被动回复），也可以用 `access_token` 主动发一条消息。

注意两点：

- `access_token` 有效期 **2 小时，必须缓存起来重复用**。不要每条消息都重新获取，否则会触发频率限制。
- 第一次配置回调 URL 时，企业微信会发一个带签名和密文的 GET 请求来**验证**这个地址。服务器要校验签名，并返回解密后的明文，验证才算通过。

**做法二：智能机器人（长连接）**

这是企业微信较新的功能。机器人可以在群里接收 @ 它的消息，通过一直保持的连接（长连接）接收，也能收发双向。可以作为备选。

### 2.2 架构：机器人只是 admincore 的又一个入口

现有的 `admin` 本身就是建在 `admincore` 上的一个入口（命令行 CLI 和终端界面 TUI）。`admincore` 提供 `CollectMachines`（收集机器信息）、`FetchLog`（取日志）、`PublishAgentUpdate`（发布 agent 更新）等功能。

**机器人只是再加一个入口**，叫 `botserver`。它做三件事：接收企业微信的回调；把消息对应到 `admincore` 的某个功能；把结果回复给用户。**不用重写，只是在外面套一层。**

```
企业微信消息  →  botserver（验签+解密+白名单）  →  admincore  →  回复
   "status"                                      CollectMachines
   "log <主机名>"                                 FetchLog
   "machine list"                                CollectMachines(bound)
```

## 3. 安全（重点）

**`admin` 程序里内置了能读写整个存储桶的密钥。** 做成机器人后，持有这把密钥的服务会变成：公网能连上（因为企业微信要回调它），而且能执行管理操作。这样的服务是攻击者眼中的高价值目标。所以必须做到：

- **单独加固回调服务。** 它要通过公网 HTTPS 访问，又持有全桶读写密钥，所以要放在单独的小服务器上，只给最小权限，并记录审计日志。
- **校验消息来源。** 校验 `msg_signature`（消息签名），确保只有企业微信能调用回调地址。
- **设白名单。** 只有指定管理员的 `FromUserName`（发送者的企业微信 userid）能发指令，其他人一律拒绝。
- **按读写分级开放：**
  - **只读**操作（`status` / `log` / `list`）通过机器人执行是**安全**的。
  - **会造成破坏或较敏感**的操作（`forget` / `disable` / `publish`）**建议不开放给机器人**，继续只在 TUI 或 CLI 里用；如果一定要开放，至少要"二次确认 + 审计 + 两人共同操作"。
- **审计。** 每条指令都记录谁发的、什么时候、做了什么。

---

## 4. 分阶段建议

| 阶段 | 做什么 | 风险 | 工作量 |
|---|---|---|---|
| **P1** | 群机器人**只读告警**（定时运行 status 巡检，结果推到群里） | 低 | 半天 |
| **P2** | 自建应用回调，做**只能查询的机器人**（status/log/list，只允许白名单里的管理员） | 中（需要公网回调地址） | 2–3 天 |
| **P3（可选）** | 开放**写操作**（publish/forget 等），严格管控 | 高 | 要谨慎评估，建议先不做 |

**做完 P1，就满足了"接入企业微信做通知"的核心需求。** 机器人是更进一步的功能，按 P2 再往前推。

---

## 5. 需要客户在企业微信那边提供什么

- **P1**：一个内部群，以及群机器人的 **Webhook URL**（管理员在企业微信里点几下就能拿到）。
- **P2**：管理员创建**自建应用**，提供 **CorpID / AgentID / Secret / 回调 Token / EncodingAESKey**，以及一个**公网 HTTPS 域名**用来放回调服务。
