# 账号打通改造计划

版本：2026-11-07（第三版）
给谁看：Peter、Wei、梦寒
对应单子：AIC-206（总任务）、AIC-207、AIC-204、AIC-208、AIC-209

## 1. 结论

**目标：** 每家客户只维护一份员工名单，放在定制工具里（Bippo 部署显示“樂山”）。员工和运维都用同一个账号，不再各开一套。

**做法：**

- **登录用 OIDC：** 这是通用的单点登录协议。控制台把用户跳到定制工具登录，定制工具把签名后的身份信息交回控制台。
- **名单靠同步：** 控制台每 5 分钟拉一次全量名单，用于开户选人和停用联动。
- **工具代码不迁移：** 定制工具和控制台仍是两个系统，分别部署。

**已确定：**

- Bippo 上线版本直接打通，不单独开工单账号。
- TEENet 运维账号也并入定制工具（老板要求）。
- Bippo 管理员从客户入口进入，身份是客户管理员。控制台的 `viewer` 只给 TEENet 内部使用。
- 账号放在定制工具，这是 2026-11-05 的决定。
- 第一版不自动关户：账号停用后先发告警，由运维人工关户，稳定后再开启。误关会直接影响员工使用云电脑和 AI。
- 控制台保留一个本地紧急账号，平时密封不用，供定制工具故障时使用。
- 运维账号在定制工具里看不到客户业务数据，也不计入员工统计。定制工具的 `is_admin` 账号会跳过权限检查，所以运维账号不设 `is_admin`。

**不在本次范围：** 无影云电脑账号仍单独开设；网关账号见 AIC-217；云电脑单点登录以后再评估；“合同工作流”不单独处理，Linear 和定制工具代码里都没有这项内容。

**工作量：** 约 18–24 人天，见第 6 节。

## 2. 架构

### 2.1 系统关系

```text
              定制工具（每家客户一套）
              账号 / 密码 / 角色 / 二次验证
                 │                │
             OIDC 登录       名单接口（每 5 分钟）
                 ▼                ▼
              控制台（每家客户一套）
                 │        │        │
              工单系统   运维后台   AI 工作间账号
                                   │ 派生员工 key
                                   ▼
        员工 → 无影验证码 → 云电脑 → Codex → LiteLLM
```

云电脑和 Codex 不走 OIDC。定制工具停机时，员工仍能用 AI；账号停用后，要等 AI 工作间关户才会吊销员工 key。

### 2.2 各角色能做什么

| 定制工具角色 | 定制工具 | 工单系统 | 控制台 |
|---|---|---|---|
| 普通员工 `employee` | 用获授权的工作流和知识库，看执行记录 | 为自己提交使用类工单（远程桌面、AI 问题、定制工具、其他），只看自己的工单。没有 AI 工作间账号时，不显示远程桌面和 AI 问题 | 不能进入 |
| 客户管理员 `admin` | 以上全部，加管理后台（账号、角色、授权） | 能提交所有类型的工单，确认待批方案，看用量（不含金额）和员工名单 | 不能进入 |
| 运维 `ops` | 能登录，看不到客户业务数据，不计入员工统计 | 不能以客户身份进入 | 定制工具账号通过 OIDC 和二次验证后直接进入；控制台本地可停用其会话主体。 |

## 3. 流程

### 3.1 登录

```text
1. 用户打开工单系统或控制台，没有会话
2. 控制台跳到定制工具
3. 定制工具检查登录状态
   ├─ 已登录且未被要求重新验证：跳过输入密码
   └─ 未登录：输入帐号和密码；管理员和运维还要过二次验证
4. 定制工具带授权码跳回控制台
5. 控制台换取并校验身份信息（ID Token）
6. 控制台按入口判断
   ├─ 客户入口：role 是 admin 或 employee 才放行；联系人不存在就当场建立
   └─ 运维入口：role 是 ops 且过了二次验证；首次登录自动建立或关联本地会话主体
7. 控制台建立自己的会话，进入 /customer 或 /overview
```

- 新账号可能赶在下一次同步之前登录，所以第 6 步要当场建立联系人。
- 运维账号也可能赶在下一次同步之前登录，所以第 6 步按 OIDC 身份当场建立本地会话主体。
- 被拒绝时只显示“此帳號無權進入”，不说明原因，并写审计。运维入口的拒绝还要发告警。

### 3.2 从定制工具进入工单

```text
定制工具点“需要幫助” → 控制台跳回定制工具 → 定制工具已登录，直接授权 → 进入工单系统
```

用户不用再输密码。工单系统不做反向跳转，AIC-207 没有这项要求。

### 3.3 会话和退出

现状：控制台空闲 30 分钟或登录满 12 小时退出。定制工具的 Cookie 没设有效期，按框架默认是 14 天，每次访问还会刷新（看代码推断，未实测）。不处理的话，控制台会话一到期就会自动重新登录，12 小时上限等于失效。

| 情况 | 处理 |
|---|---|
| 运维会话到期 | 每次进入控制台都重新验证密码和二次验证（OIDC 的 `prompt=login`） |
| 客户会话到期 | 允许自动重新登录，但定制工具的会话缩短到合理时长（建议 12 小时，阶段 1 确认） |
| 在工单系统点“登出” | 同时退出定制工具，否则下一次访问又会自动登录 |
| 在定制工具点“退出” | 工单系统会话等空闲超时后失效，第一版接受这个差异 |

### 3.4 员工入职

```text
客户管理员在定制工具建账号，并授权工作流
  → 员工立即能用定制工具和工单系统
  → 5 分钟内同步到控制台名单
  → 客户管理员提交“新增 AI 工作间账号”工单，从名单选人
  → 运维在无影开云电脑，在控制台开户（Worker 派生员工 key）
  → 员工开机，Agent 上报，运维绑定机器，Agent 写入 key
  → 员工用 Codex 发一句话验证，工单完成
```

### 3.5 提交和处理工单

```text
员工或客户管理员提交工单（保存提交时的帐号和显示名称）
  → new：运维在 /tickets 看到
  → working：运维处理
  ├─ 涉及额度、费用或删除：运维提出方案 → 客户管理员确认 → 执行
  ├─ 需要补充信息：waiting_customer → 客户回复 → working
  └─ 完成：done → closed
```

工单处理人显示运维本人的名字，不再是共用账号。

### 3.6 员工离职

```text
客户管理员提交离职工单，并停用定制工具账号（先后顺序由 AIC-201 确定）
  → 定制工具当场拒绝登录
  → 5 分钟内同步：清除工单和控制台会话
  → 有 AI 工作间账号：发告警，运维关户（吊销员工 key、撤回配置、关掉 Codex）
  → 客户确认后，运维交接资料、释放实例
```

如果只停用账号、没提工单，系统照样收回权限，并用告警提醒运维跟进。开启自动关户后，关户这一步由系统完成，审计记为“系统联动关户”，但不释放实例、不删除数据。

### 3.7 名单同步

控制台 Worker 每 5 分钟拉一次名单，写入本地副本，再处理变化：

| 变化 | 控制台的动作 |
|---|---|
| 新账号 | 非运维账号建立工单联系人 |
| 改名 | 更新当前显示名称，已有记录保留当时的名字 |
| 角色变化 | 更新工单权限。运维权限不自动变化，只发告警 |
| 改邮箱 | 不自动改无影，发告警提醒同步 |
| 停用或删除 | 清除工单和控制台会话；有 AI 工作间账号的发告警 |
| 重新启用 | 恢复工单登录；AI 工作间不自动恢复，发告警 |

AIC-204 要求的“马上不能登录”按此实现：新登录由定制工具当场拒绝，已登录的会话最迟 5 分钟内失效。

### 3.8 定制工具不可用

| 功能 | 影响 |
|---|---|
| 云电脑、Codex、AI 调用 | 不受影响 |
| 已登录的工单和控制台会话 | 到期前不受影响 |
| 新登录工单系统和控制台 | 不能登录；运维只能用紧急账号 |
| 名单同步 | 暂停并告警，不触发任何停用 |
| 客户报障 | 走不依赖登录的备用渠道（比如群或邮箱，阶段 1 定） |

## 4. 安全规则

**运维账号的保护：** 定制工具账号将决定谁能操作控制台，所以以下规则都要满足。

1. **白名单：** 定制工具里的 `ops` 角色本身不开放控制台。控制台管理员把它绑定到一个控制台账号后才能进运维后台。没绑定的运维账号登录时，页面提示"尚未开通，已通知管理员"；该账号进入 `/admins` 的"待开通"列表，同时发告警。管理员点"建立并绑定"即可开通，新账号没有密码，只能经定制工具登录。本人已有控制台账号的，点"绑定"。
2. **二次验证：** 运维和客户管理员都必须开启。控制台检查登录结果的 `amr`，不含 `otp` 就拒绝运维登录。
3. **角色隔离：** 只有运维能授予或修改 `ops` 角色。客户管理员看不到、也改不了运维账号。
4. **紧急账号：** 只保留一个本地账号，平时不用。一旦登录，立即发告警并写审计。
5. **重新验证：** 运维入口要求 10 分钟内在定制工具输入过密码和验证码（`max_age=600`，控制台核对 `auth_time`），超过就重新输入。

**防止批量误关：**

1. 只有明确的 `disabled` 或 `deleted` 才算停用。账号从名单消失、接口报错或返回空名单，都不触发。
2. 一次同步要停用的账号超过 3 个时，这批不处理，发告警等人工确认。
3. 连续同步失败超过 15 分钟发告警。

## 5. 改动清单

以下现状基于 2026-11-07 核对的代码：定制工具为远端 `main` 的 `01fd688`，控制台为 `bda568e`。

### 5.1 定制工具（FastAPI + SQLite，AIC-207）

| 现状 | 要改成 |
|---|---|
| 账号 ID 是自增整数，且会复用：删掉 ID 最大的账号后，新账号拿到同一个 ID（已用相同表结构实测） | 增加不复用的 `uuid`，存量账号回填。否则工单和 AI 工作间可能对应到别人 |
| 删除账号直接删记录（`admin_routes.py:410`） | 改为软删除（`deleted_at`），已删除账号不能登录，也不占用帐号名 |
| 角色只有 `is_admin` | 增加 `role`；`is_admin` 暂时保留，避免影响现有权限判断。运维账号不设 `is_admin` |
| 没有二次验证 | 管理员和运维必须开启，并提供恢复码 |
| 没有单点登录 | 提供 OIDC 登录和退出，支持 `prompt=login` |
| 没有名单接口 | 新增只读接口，格式见附录 A |
| 客户管理员能管所有账号 | 后台隐藏运维账号，限制修改运维角色 |
| Cookie 没强制 HTTPS（`main.py:118`），也没设有效期 | `https_only=True`，并设置会话时长 |
| 没有停用提醒和帮助入口 | 增加“停用前提醒”和“需要幫助”（AIC-207 第 4、6 条） |

### 5.2 控制台（Go + PostgreSQL，AIC-204、AIC-208、AIC-209）

| 现状 | 要改成 |
|---|---|
| 客户和运维都用本地密码登录 | 增加 OIDC 登录、回调和退出，客户和运维入口分开 |
| 只有一种部署方式 | 增加 `AIENVMGR_IDENTITY_MODE`：`local`（默认）保持现有登录，给没有定制工具的客户用；`oidc` 关闭密码登录（紧急账号除外） |
| 没有名单副本 | 迁移 `0025`：新建 `directory_accounts`；`customer_contacts`、`admin_principals`、`employees` 增加 `directory_id`；两张账号表的 `password_hash` 改为可空；运维首次 OIDC 登录时按工具账号自动建立本地会话主体 |
| Worker 没有名单同步 | 增加同步任务和第 4 节的保护规则 |
| 联系人能新增、重置密码、改角色和停用（`server.go:437-441`） | `oidc` 模式下改为只读 |
| 登录页是密码表单 | `oidc` 模式下改为“使用樂山帳號登入”，隐藏改密码入口 |
| 工单提交人没有快照 | `tickets` 增加提交人帐号和显示名称 |
| 运维账号有共用账号 | 一人一个，显示本人名字；停用 `customer` 和 `admin-g6nujg` |
| 工单类型只按角色区分 | 没有 AI 工作间账号的普通员工，不显示远程桌面和 AI 问题 |
| 开户手填姓名和邮箱 | 控制台和工单都从名单选“还没有 AI 工作间账号的人”。Windows 用户名、部门、预算和模型仍在控制台填 |
| 员工记录不关联定制工具 | 列表显示关联状态；机器绑定、用量和审计用定制工具的名字，并保留当时的名字 |
| “修改员工信息”工单能改姓名和邮箱 | 去掉这两项 |
| 关户只能人工触发（`admincore/account.go:134`） | 复用现有实现，增加自动关户开关，默认关闭 |

## 6. 排期和上线

工作量是按代码现状的粗估，需要负责人确认。阶段 2 和阶段 3 可以同时开发，控制台先用模拟的 OIDC 服务联调。

| 2. 改定制工具 | 梦寒 | 第 5.1 节 | 5–7 天 | 测试客户端能走通登录，名单返回三种角色和三种状态 |

## 7. 验收

AIC-206 的总体验收加上以下情况，都在测试环境用测试账号验证。

**正常流程：**

| 编号 | 操作 | 预期结果 |
|---|---|---|
| 1 | 新建员工，从名单选他开 AI 工作间 | 开户成功，已关联 |
| 2 | 用这个账号登录工单系统并提交工单 | 不用再输密码；提交人是定制工具名字 |

| 7 | 新账号在下一次同步前登录工单系统 | 能登录，联系人当场建立 |
| 8 | 从定制工具点“需要幫助” | 不用再输密码，直接进入工单系统 |
| 9 | 在工单系统点“登出”后再打开 | 要重新输入密码 |

**权限和异常：**

| 编号 | 操作 | 预期结果 |
|---|---|---|

## 8. 主要风险

| 风险 | 后果 | 应对 |
|---|---|---|
| 定制工具成为单点 | 它停机时，客户和运维都不能新登录 | 紧急账号；客户报障备用渠道 |
| 定制工具被攻破 | 攻击者可能冒充员工，影响工单和名单 | OIDC 签名校验、二次验证、角色校验、批量停用保护 |
| 定制工具的数据库丢失 | 所有系统都失去账号来源。它用 SQLite，现有备份是否够用还没核对 | 阶段 2 核对备份和恢复方式 |

## 附录 A：接口约定

阶段 1 由 Wei 和梦寒确认，之后两边按它分头开发。

**登录：** OIDC 授权码模式，并启用 PKCE（防止授权码被截获后冒用）。控制台校验 ID Token 的签名、签发方、受众、有效期和 nonce。

| 字段 | 内容 |
|---|---|
| `sub` | 账号 UUID，创建后不变、不复用 |
| `preferred_username` | 帐号 |
| `name` | 显示名称 |
| `email` | 邮箱 |
| `role` | `ops`、`admin` 或 `employee` |
| `amr` | 本次登录的验证方式。过了二次验证时包含 `otp` |

**名单：** `GET /internal/directory/accounts`，用单独的令牌鉴权，只给控制台使用，返回全部账号。已删除的账号也要继续返回。

```json
{
  "generated_at": "2026-11-07T08:00:00Z",
  "accounts": [
    {
      "id": "UUID，与 sub 相同",
      "username": "a@example.com",
      "name": "显示名称",
      "email": "a@example.com",
      "role": "employee",
      "status": "active"
    }
  ]
}
```

`status` 取 `active`、`disabled` 或 `deleted`。

**配置（每家客户一套，只放在 `console.env`）：** 定制工具地址、OIDC 客户端 ID 和密钥、名单令牌、登录按钮上显示的工具名称。
